## 1. 项目目标与交付层次

核心目标：在 Unity 中自行实现 FK、IK 和形状求解，根据目标胶囊体的几何快照与一个抓取进度参数，计算多关节手臂、手腕及五指的姿态，并以可解释、可复现的方式验证。

泳池与巨手是应用情境；数学求解、约束处理、实验与解释构成课程主线。

交付分为两个层次：

1. **抓取原型**：采样、目标生成、伸手、转掌、张手、包覆、接触评估与进度查看。
2. **课程完整交付**：在原型基础上补齐解析、迭代、形状三类求解器、统一接口、自设计方法、批量实验、连续动画与报告。原型功能完成不等于最高档要求全部完成。

## 3. 首版使用流程

1. 进入演示，控制玩家移动。
2. 点击“采样玩家当前位置”。
3. 读取真实目标胶囊的几何参数并复制数值，生成目标版本号。
4. 显示采样胶囊代理、中心和轴向；进度归零，旧轨迹缓存失效。
5. 为该快照与固定配置生成本次抓取目标及轨迹。
6. 拖动进度条，查看对应姿态、接触与误差。
7. 玩家此后移动不改变已采样目标；再次采样才更新。
8. 参数无效、不可达或求解失败时，显示具体状态与误差，不把失败姿态标记为成功。

没有有效采样前，进度查看不可用。采样不等于暂停整个 Unity，也不自动移动玩家或手臂根部。

## 4. 系统输入与输出

### 4.1 外部输入

| 输入 | 含义与约定 |
|---|---|
| 胶囊中心 C | 世界坐标的真实几何中心，不能默认等于 Player 根节点位置 |
| 胶囊轴向 u | 世界坐标单位向量；首版建议使用现有竖直主控，数据接口仍保留轴向 |
| 半径 r、总高度 H | 世界单位；r>0，H>=2r；无效值明确报告 |
| 抓取进度 s | 限制在 [0,1]；控制任务阶段，不直接代表接触力或压力 |
| 采样命令 | 复制几何数据，替换目标快照，清理本次规划状态 |

若目标来自 Character Controller，应转换组件 center 等局部参数，不能直接把视觉网格或根节点原点当作胶囊。首版建议要求单位缩放；非均匀缩放的精确胶囊拟合暂不纳入首版。

### 4.2 固定配置与标定数据

- 肩部或骨链根部世界变换；抓取期间根部位置固定。
- 父子索引、静止局部变换、骨长、骨骼主轴、各关节自由度与限位。
- 腕部到 PalmFrame 的固定刚性变换。
- 各指根在掌部的固定位置；各指段长度、局部轴与默认姿态。
- 指节简化体积、指腹接触区域、掌部代理体。
- 接近侧偏好、抓取区域、候选方位、手臂形状偏好。
- 求解误差阈值、迭代预算、步长等算法参数以及实验随机种子。

这些属于系统配置，不要求全部暴露为玩家滑条。当前 Grip 收紧角度不自动等于关节合法限位。

### 4.3 输出

- 所有关节的局部旋转，以及自写 FK 重建的世界位置与旋转。
- 掌部、手腕和各指的目标/目标区域及候选信息。
- 各进度样本的姿态、接触集合、间隙、穿入深度与相关误差。
- 求解状态、阶段、迭代次数、耗时、回退说明。
- 可回放的数据与实验记录；不是只输出 Line Renderer 点集。

## 5. 功能需求与验收要点

| ID | 功能 | 验收要点 |
|---|---|---|
| F01 | 目标快照 | 玩家离开后快照不变；重新采样才更新中心、尺寸及轴向 |
| F02 | 几何目标生成 | 胶囊变化后重新计算掌心、腕点、各指接触候选；可独立显示这些目标 |
| F03 | 多关节手臂求解 | 根部与骨长固定，输出完整骨链姿态；不以伸缩或移动根部掩盖不可达 |
| F04 | 掌部与手腕姿态 | 同时考虑掌心位置和朝向；通过固定腕掌变换得到腕部目标，再结合前臂结果计算局部腕旋转 |
| F05 | 通用单指求解 | 五指复用框架，通过骨长、轴、限位、接触区域等配置区分；不强制所有指尖到同一个点 |
| F06 | 自写 FK 与旋转恢复 | 从局部变换重建骨架，核对 IK 位置结果；初始采集可以读 Transform，但不能用引擎自动算好的位置冒充自己的 FK |
| F07 | 进度与轨迹 | 支持正向、反向、跳转查看；同一快照/配置/进度的结果在数值容差内可复现 |
| F08 | 接触与穿插评估 | 检查允许接触区域和完整骨段代理；不只检查指尖；相邻结构正常重叠的排除规则要明确 |
| F09 | 状态与回退 | 区分无输入、无效配置、成功、部分接触、明确不可达、当前抓法不适用、未收敛及数值失败 |
| F10 | 技术视图 | 显示目标胶囊、参考形状、关节轴、实际骨链、目标误差和接触状态 |
| F11 | 实验模式 | 支持可拖动的求解目标、程序化连续轨迹、固定随机种子的测试与结果导出 |
| F12 | 单一姿态输出 | 多个算法返回数据，由统一出口更新显示；旧 Grip 驱动与新 IK 不得同时覆盖同一关节 |

F07 的具体实现建议为：从相同初始姿态按固定规则生成轨迹，再由进度采样。任何缓存插值结果也需验证，不能仅凭关键帧无穿插就声称整个连续轨迹无穿插。

游戏模式采用静态胶囊快照，实验模式另外提供动态求解目标；两者通过同一数学接口工作，不互相替代。

## 7. 硬约束、任务条件与偏好

### 7.1 必须保持的结构与安全约束

- 固定根部位置与骨长，使用单位缩放的骨架约定。
- 关节不越过已标定限位。
- 不产生 NaN、无穷值或无限迭代。
- 抓取轨迹的被检验样本中，目标物与非相邻手部代理不得超过允许穿入容差。
- 掌部保持刚性，指根相对掌部的位置固定。

### 7.2 最终抓取任务的建议定义（待确认）

- 最终需要拇指与至少两根其他手指形成有效指腹/指节接触。
- 接触从不同侧构成包围，具体对向角阈值在标定后固定。
- 掌部接触与其余手指贴合先作为质量项，不强制五个指尖都接触。
- 接触不足只能报告部分接触；不能等同于抓取完成。
- “抓取完成”是运动学任务状态，不代表已证明力封闭或能靠摩擦抵抗重力。

### 7.3 可优化的偏好

- 手臂接近指定参考形状，腕部少扭转。
- 指形接近定义的默认抓握姿态，避免不必要的反折。
- 接触间隙更小、有效接触更多、帧间旋转变化更小。
- 掌位、抓取高度和接触角可在允许范围内协同调整。

物体表面的有效接触比某个初始掌位猜测更重要。目标生成器给出的掌位是候选/内部目标；协同求解可在允许范围内调整它，不必把它永远锁死。

优先级建议：结构与安全合法 → 满足抓取接触任务 → 形状与姿态偏好 → 连续性与计算成本。不能以较好看的姿态抵消严重穿入。

## 8. 几何目标生成的设计接口

目标生成在 IK 之前，独立于 Unity 显示层。它不直接输出“每个关节转多少度”。

1. 由肩部、胶囊中心与轴向确定接近侧，退化时使用已标定方向。
2. 由胶囊半径、抓取高度、掌部厚度与间隙生成掌心候选。
3. 建立掌部目标方向，通过腕掌固定变换得到手腕目标。
4. 由指根布局、胶囊表面与允许接触区生成各指候选。
5. 接触目标根据进度从预抓取状态接近表面；由求解器检查可达性并求旋转。

几何约定：设 a=H/2-r，胶囊轴段为 [C-au,C+au]。位于轴向高度 z 的横截面半径为：

```text
rho(z) = r                              当 |z| <= a
rho(z) = sqrt(r*r - (|z|-a)^2)           当 a < |z| <= H/2
```

沿表面的接触点需要结合 z 与绕轴角 theta 计算；指尖中心目标还需沿表面法线加上指尖代理半径。高度超出有效区间时不得通过把多个目标夹到同一点来掩盖不适用。

单纯增加一根长胶囊的高度，若接触仍在同样的圆柱区域，指形不一定需要改变。这是合理几何结果。

## 9. 模块与系统外部的边界

| 模块 | 输入与输出 | 不承担的责任 |
|---|---|---|
| Unity 输入适配 | 读取玩家组件与控制台事件，输出数值快照 | 不直接修改手指旋转 |
| 目标生成 | 胶囊、骨架配置、进度 → 掌/腕/接触目标 | 不假定目标必然可达 |
| 手臂求解 | 根部、骨长、目标与形状参数 → 骨链姿态 | 不修改玩家或物体尺寸 |
| 腕部求解 | 掌部目标、前臂 FK 结果、腕掌标定 → 局部旋转 | 不通过平移腕骨改变骨长 |
| 通用手指求解 | 各指骨架、限位、接触候选 → 各指旋转与误差 | 不各自独立抢写掌部姿态 |
| 自写 FK | 骨架、根部与局部变换 → 世界变换 | 不把 Transform 的层级结果当作自身计算 |
| 总控/轨迹调度 | 快照、进度、配置 → 按顺序调用/必要时协调迭代 | 不隐藏求解失败 |
| 评估与显示 | 读取目标、姿态、误差、接触与状态 | 不反向覆盖数学输出 |

基础调用顺序：目标生成 → 手臂 IK → FK 得前臂变换 → 腕部求解 → FK 得掌与指根变换 → 手指求解 → 完整 FK → 评估 → 显示。研究方法可增加有预算的掌指协调循环。

模块是职责边界，不强制每项对应一个 MonoBehaviour。矩阵/四元数库和通用线性求解器可作为工具；核心 FK、IK 更新、形状建模与约束处理自行组织实现。

Unity C# 是正式演示的运行端。现有 Python 项目可用于推导、测试与独立核对，不要求维护两套完整产品，也不在每帧启动 Python。

## 10. 状态、可复现性与数值边界

- “明确不可达”需要距离界等可说明的依据；迭代次数用完只能报告未收敛，不能据此证明无解。
- 自由串联链的距离界为 r_min=max(0,2*l_max-L)，r_max=L；关节限制和形状族还会进一步缩小可行域。
- 相同快照、骨架、配置、算法版本、种子与进度，应得到容差内一致的姿态；记录分支选择与回退。
- 接近完全伸直、目标接近根部、轴向与接近方向共线、短胶囊接近球形、非等长骨段均需显式测试。
- 球形极限下，轴向对称性更强；可以使用明确的偏好/回退或报告当前抓法不适用，但不得出现除零或 NaN。
- 允许预计算与缓存轨迹；记录总规划耗时，不只记录显示帧率或位置迭代的一部分耗时。
- 性能预算、关节角和支持尺寸域在标定后固定，首版不提前承诺任意规模都能实时求解。

## 11. 误差与成功指标

课程文档给出了归一化误差阈值，但未完整展开计算公式。本项目暂采用下列口径；正式提交前核对并在报告中明确。

| 指标 | 暂定定义/要求 |
|---|---|
| 末端误差 e_pos | FK 末端到目标的距离 / 当前链总长 L |
| 骨长误差 e_len | max_i(abs(实际骨段长-l_i)/l_i) |
| 朝向误差 | 目标与 FK 末端旋转之间的夹角，记录单位 |
| FK 重建差异 | FK 点集与 IK 位置结果的最大距离 / L |
| 接触间隙 | 允许接触部位到物体表面的正间隙 / r |
| 最大穿入 | 检查代理的最大穿入深度 / r |
| 连续性 | 相邻固定进度样本间的关节旋转角变化 |
| 成本 | 总耗时、位置迭代/旋转恢复/FK/检查耗时与迭代次数 |

课程基础验收：固定随机种子、至少 1,000 个可达目标，平均 e_pos < 1e-3，每例 e_len < 1e-3，另测不可达和退化情况。可通过 FK 构造已知可行的目标，不能只按“距离小于总骨长”生成所谓可达集。

抓取原型建议初始阈值：接触正间隙 <= 0.02*r，允许穿入 <= 0.005*r。这是待标定的工程初值，不是物理抓稳标准，也不替代课程骨长/末端指标。

轨迹检查建议初始使用 101 个进度样本，并在阶段切换和接触附近增加样本；需要验证插值姿态。有限采样不能被表述为严格的连续零碰撞证明。

研究课题候选：单进度、尺寸自适应抓取中的掌部与多指协同。普通 Grip 和“固定掌位+各指独立 IK”可以作为应用基线；研究方法应说明掌指协调、接触分配或形状控制中的具体新设计。并列运行几根手指 IK、只换曲线公式、只增加漂亮渲染都不能自动视为完成研究扩展。

当前不宣称方法已完成、已优于基线或具备学术新颖性。具体算法与研究假设在需求明确、相关工作梳理和小实验后确定。

## 14. 待确认项与关键风险

| ID | 待确认内容 | 决策依据 |
|---|---|---|
| D01 | 最低有效接触集合、是否要求掌部接触、对向阈值 | 先让几何代理与希望的抓法一致，再固定实验标准 |
| D02 | 支持的胶囊尺寸域与抓取空间 | 由固定手型、骨长、限位标定；包含不适用与不可达样本 |
| D03 | 初始姿态、阶段区间及重叠方式 | 保证张开/转掌发生在安全接近阶段，不能只优化最后一帧 |
| D04 | 掌部参考架、腕掌偏移、各指骨轴与限位 | 先校准固定几何；静止姿态不等于零旋转，收紧角不等于限位 |
| D05 | 自设计研究方法与具体假设 | 基线运行后用失败案例确定；不靠算法数量或界面复杂度代替研究 |

关键风险及处理：

- 现有两段手臂的总长未必能到玩家出生区：如实报告并规划多段实验骨链，不偷偷移动根部或拉长骨段。
- 过早固定五个指尖点可能制造不可行任务：采用有明确边界的接触区域，并保留部分接触/失败状态。
- 多组件同时写关节会覆盖结果：统一求解调度与唯一输出，保留旧模式用于对照而不是并发写入。
- 接触判据与物理抓稳混淆：首版只认运动学几何结论。
- 参数太多掩盖数学问题：玩家只保留采样和进度，算法参数在技术/实验界面记录与固定。
- 环境、美术、动态追踪、供给机构一起推进会扩大范围：优先通过输入层、FK、基线与抓取评估，再扩展。

下一项建议工作：先完成 D04 的最小标定和 M1 的采样/几何目标显示，让输入中心、轴向、掌心、腕点、各指目标及坐标系都能独立检查；本轮不把尚未标定的接触阈值或限位当作最终确定值。
