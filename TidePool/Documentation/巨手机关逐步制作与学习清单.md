## 第二轮：手写 Two-Bone 的位置求解

### 文件与输入输出

在 `GiantHand/Math` 创建纯 C# 类 `TwoBoneSolver.cs`。它不是要挂在物体上的组件。

输入：Root、Target、Pole、L1、L2。输出：肘点、求解后的腕点、弯曲平面与求解状态。不要在这个类里读取键盘或寻找场景对象。

### 按顺序写的计算

1. 检查骨长有效，计算 `d=|Target-Root|`。
2. 取得目标方向 `x=(Target-Root)/d`；根部重合的回退稍后补。
3. 将 `Pole-Root` 去掉沿 x 的分量，得到垂直方向，再归一化为 y。
4. 用余弦定理计算 `a=(L1²+d²-L2²)/(2d)`。
5. 计算 `h=sqrt(max(0,L1²-a²))`。
6. 肘点为 `Root+a*x+h*y`。
7. 验证两段距离分别为 L1、L2。

对应复习 Python：`D:/awestlakeselfstudy/shape_ik_project/src/two_bone.py`，逐项比较变量，不整段黑箱搬运。

### 本轮怎样显示

调试组件调用求解器，先用另一种颜色画“计算出的骨链”，现有实体手臂暂时不动。这能先检查数学方向，不让模型轴向问题掩盖算法错误。

### 验收

- 等边三角形例子：Root=(0,0,0)、Target=(1,0,0)、Pole=(0,1,0)、L1=L2=1，得到肘点 (0.5,sqrt(3)/2,0)。
- 对巨臂的正常可达目标，两段骨长保持。
- Pole 翻到另一侧，肘点选择相应分支。
- 上面是位置解，不能据此宣布完整骨骼 IK 已完成。

## 第三轮：把位置解变成关节旋转，实体巨臂跟随

### 需要写什么

1. 新建 `GiantArmRigDriver.cs`，挂在机关根节点。
2. 填入 UpperArm、Forearm、Wrist、Target、Pole 引用。
3. 记录静止姿态、骨轴与参考弯曲方向，提供明确的“记录参考姿态”操作。不要每帧把上一帧解出的姿态重新当参考姿态。
4. 根据解出的上臂方向、前臂方向和弯曲平面建立世界旋转。
5. 考虑骨骼沿 +X 的约定，使用正确轴映射；不能直接把默认沿 +Z 的朝向结果套进去。
6. 使用父旋转的逆换算局部旋转，依次驱动 UpperArm 和 Forearm。
7. Wrist 的位置由层级产生，不直接将 Wrist.position 强行设置到 Target 来掩盖误差。
8. 暂时固定 IK Weight=1，关闭动画平滑，先验证精度。

### 验收

拖 Target 后，真实上臂、前臂和手掌占位模型跟随。

显示并区分：

- 求解出的腕点到 Target 的误差。
- 实际 Wrist 世界位置到求解腕点的 FK 回代误差。
- 实际两段骨长误差。

对可达目标，数学解与实体骨架都应满足预设精度。伸不到的 Target 不能用同一成功标准评价，应有不可达状态。

## 第四轮：做出类似 Houdini 的编辑器实时调参体验

### 参数面板

在现有驱动组件基础上组织 Inspector：

| 参数/信息 | 作用 |
|---|---|
| Preview In Editor | 编辑模式启用/停用求解预览 |
| Target / Pole | 目标引用；可在 Scene 中拖动 |
| IK Weight | 从固定参考姿态到求解姿态的混合权重 |
| Solve / Restore Reference | 单步求解与恢复参考姿态 |
| Show Debug | 辅助线和求解数据 |
| Length 1 / Length 2 | 初期只读显示实际长度 |
| Reachability / FK Error | 当前状态与误差 |

初期不提供与实际骨架脱节的“骨长滑块”。后面若开放长度参数，要同时更新子关节偏移和 Visual 几何长度。

### 更新机制

1. 增加明确的编辑模式预览开关，使用 ExecuteAlways 等编辑器执行机制。
2. 目标或参数变化后重新求解，更新 Scene 显示；不在预览循环创建、删除骨架。
3. OnValidate 主要负责数值校验；必要的场景更新通过合适的编辑器更新过程执行。
4. 编辑器修改支持撤销、恢复参考姿态；停用预览后能重新进行手动 FK。
5. Play 模式继续调用相同数学求解器，不另写一套游戏版公式。

### 验收

不按 Play，拖 Target/Pole 和修改权重，场景立即变化。能停止预览、恢复参考姿态，修改不会影响其他场景或其他机关实例。

这就是第一项完整里程碑：**自己的可视化 Two-Bone IK 工具**。

## 第五轮：处理边界、限位和连续运动

1. 为不可达目标创建明确状态。无关节限位时，腕部可达距离为 `|L1-L2|～L1+L2`；8、7 对应约 1～15 米。
2. 太远或太近时，对求解目标进行夹紧；保留原始 Target 用于显示误差，不能改掉目标后假装完全命中。
3. 接近根部、Pole 共线、近乎伸直时使用稳定备用方向/上一帧有效平面，并记录回退状态。
4. 防止手臂跨过伸直位置时突然翻肘；连续移动目标观察，不只测试静止截图。
5. 再加入目标速度限制或平滑。测精度时关闭它，区分延迟与求解误差。
6. 限制工作区并检查整段骨架是否穿墙/穿顶；目标合法不代表上臂、肘和手指都合法。
7. 第一版用经过验证的工作区与 Pole 约束保证主要动作；通用避障后续再做，不声称基础 IK 自动避障。

验收：远、近、共线、伸直及 10 秒连续轨迹不产生 NaN、异常跳飞或骨长漂移。随后扩充到课程要求的固定种子随机目标与归一化误差报告。

## 第六轮：让手掌能独立旋转

1. 将 WristTarget 的 Rotation 作为期望的手掌世界朝向。
2. 在手臂位置解完成后，计算腕部相对前臂的局部旋转。
3. 定义手掌法线、向指尖方向和腕关节轴，保留外观偏移。
4. 第一版以腕点为位置目标：转掌时腕点固定，掌心可能绕腕运动，这是正确的几何结果。
5. 新建 PalmContact 空物体标记实际掌心接触位置。
6. 若要固定接触位置，改用 `腕目标=接触目标-手掌目标旋转×腕到接触点局部偏移`，再求手臂。
7. 加入腕部屈伸、侧偏和扭转限制；后面再研究前臂分担扭转。

验收：编辑模式旋转目标，手掌改变朝向；不破坏手臂骨长或腕点位置精度。

## 第七轮：搭建五指骨架，先做 FK 手势

1. 在 Wrist 下建立 PalmRoot，掌骨几何跟随它。
2. 从食指开始，依次建立三段关节与一个指尖标记。每节 Visual 是独立子物体。
3. 确定局部长度轴和屈曲轴；转单个指根，确认后面的关节都跟随。
4. 复用结构建立中指、无名指、小指，调整骨长和横向位置。
5. 拇指先两段，加根部外展/对掌控制，不能只把普通手指横着复制过去。
6. 编写 FingerPoseController：curl=0～1 对应各节屈曲角度；每节有自己的最大角度。
7. 增加整手张合、单指张合与张开程度参数。
8. 保持关节限位，检查手指是否反折、互相严重穿插或穿过掌部。

验收：Inspector 中调整手势，巨手能张开和收拢，腕部旋转时整只手跟随。

这属于 FK 姿态控制，先明确标注；指尖自动找位置是后面的 IK。

## 第八轮：玩家从出生点控制机关

1. 在出生点现有控制台附近增加 F 进入提示与距离判断。
2. 编写 GiantHandControlSession，显式区分普通移动与机关控制状态。
3. 进入时记录玩家移动、CameraFollow 和光标状态，暂停冲突输入，切到能看清巨手的操控视角。
4. 方向键按面向远墙的坐标系移动 Target；之后增加 PageUp/PageDown 的深度控制。
5. 右键拖动设置手掌目标朝向；Z/X 负责滚转；Space 设置张合。
6. Esc/F 退出时恢复原来的玩家、相机和光标状态，不简单地把所有组件无条件设成启用。
7. 处理原有 E 排水、Space 跳跃、右键相机、R 重置冲突，避免同一次输入被两套系统消费。
8. F1 打开调试显示：目标、Pole、实际末端、误差、状态；正常模式保持画面简洁。

验收：可在初始位置进入、控制、退出、再次进入；人物不会同时跑动或跳跃；退出后原相机操作正常。

## 第九轮：接收板解谜与现有关卡联动

1. 在远墙侧面放掌形接收板，避开出口和最终干区。
2. 标记目标掌心位置、期望掌心法线，以及未来五指的接触点。
3. 第一版检查实际 PalmContact 的位置、实际掌心法线夹角和张开参数；不以 Target 自身的位置判定成功。
4. 显示位置/朝向/手势的渐进反馈；连续满足约 1 秒才完成。
5. 首轮成功只亮起接收板，确认可重复完成。
6. 再通过一次性完成事件连接原有 PoolWaterCycle.TryInteract，开始排水；不在纯求解器里修改水位。
7. 给原 E 排水入口加状态门控，防止绕过机关。
8. 保持现有排水露信、拾信渐暗、涨水、干区流程。
9. R 重置同机关：Target、Pole、腕部旋转、手势、成功状态、控制模式、相机和关卡水位一起恢复。

验收：巨手完成接触→排水→拾信→淹没→重置，一条流程通顺，不重复触发。

## 第十轮：指尖 FABRIK 与 Shape IK 拓展

### 指尖 FABRIK

1. 用一根三段手指作实验，为指尖放 Target。
2. 自己实现前后向迭代，每一步保持骨长，设置末端误差与最大迭代次数。
3. 加入合理弯曲平面与关节角度限制；普通无约束 FABRIK 不会自动形成真实手指动作。
4. 恢复局部旋转，通过实际指尖 FK 验证。
5. 推广到四根手指，拇指先独立处理根部对掌与两段求解。
6. 用接收板五个实际接触点驱动指尖，替换早期的“仅检查张开参数”。

### Shape IK

1. 在独立多段链上先验证圆弧等形状先验，再应用于多节手指/后续角色结构。
2. 用端点、骨长和弯曲偏好求形状参数，不把固定握拳角度改名为 Shape IK。
3. 等弧长采样不等于离散骨长正确；需要求交、反求或约束修正。
4. 明确骨长与端点约束、形状偏好的取舍，报告不可行或回退状态。
5. 姿态转局部旋转，再 FK 重建，展示形状参考、骨架和实体外观。
6. 比较解析、迭代、形状方法的误差、连续性、代价和失败情况。

课程如要求特定角色应用，后续还要把框架接到简化人形或其他明确角色结构，不能仅凭机关演示就宣布满足所有课程条目。

## 每轮写代码的方式

1. 先讲输入、输出、坐标系和公式，手算一个小例子。
2. 你逐段写函数；每写一段就让辅助显示呈现结果。
3. 在同一输入上对照 Python 与 Unity。
4. 加一个正常案例和一个边界案例。
5. 记录今天改了什么、误差多少、哪里仍不理解。
6. 保存场景和代码，再进入下一轮。不一次性塞入完整黑箱脚本。
