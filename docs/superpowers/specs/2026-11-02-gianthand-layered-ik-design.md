# GiantHand：分层 IK / FK 与自动抓取设计

日期：2026-11-02

修订：2026-11-03，根据用户逐项反馈调整。

状态：分层路线、大部分大厅可达且允许部分角落不可达、静止人物优先、3 秒采样、动作时序、五指成功标准和运行参数可调已确认；具体总骨长待根据大厅测试点核定。本文是设计，不表示下述求解器已经实现。

场景：Unity 项目 `TidePool`，主要应用场景 `Assets/_Game/Scenes/PoolHall_ArmLab_01.unity`。

## 1. 要做成什么，以及为什么

目标是把已经确认效果的浏览器抓取示意，转化为可解释、可验证的骨骼求解程序，并满足《Project 2：From FK to Shape IK —— 可解释的骨骼 IK 求解器》的基础档、进阶档要求，在此基础上完成研究扩展。游戏情景用来展示数学结果；模型精美程度和完整游戏流程不作为主线。

用户已经确定：

- 手臂增加为多段关节，可以在开始时选择圆弧、波形或螺旋形状。
- 手臂最大运动范围应覆盖大厅大部分可站立区域；部分角落允许不可达，作为有意保留的失败用例。第一阶段在这个总体范围目标下逐个测试静止人物位置。
- 第一阶段人物静止站在指定位置，先验证手臂关节计算、掌部朝向与合理包覆；移动人物追踪作为后续阶段。
- 采样周期先设 3 秒，手掌按周期读取人物位置并发起一轮抓取；一轮内固定目标快照。
- 掌心中的接触标记点碰到人物外围胶囊时，触发人物移动锁定。
- 随后手指包覆、短暂停留、松手、复位，可以反复观察。
- 浏览器示意中的侧面接近、掌心朝向人物、四指与拇指对向包覆符合预期。
- 采用 A：先确定掌部位置与方向，再求手臂，最后分别求手指。
- 手指够不到时，需要明确报告失败或调整抓取目标。
- 原有手掌、手臂和手指以关节点及自动连线为主要可视化；新增关节接在手臂靠根部的一侧，保留原有手部结构与骨长。初始化时可以整体前移原结构。
- 包覆 1 秒、停留 1 秒、张手 0.5 秒、复位 1 秒、等待下一轮 0.75 秒；五指全部达到接触区域并通过检查才算包覆成功，部分成功单独显示并释放。
- 接近方位、滚转、采样周期、包覆时间、形状参数、误差阈值和迭代上限都可在运行面板调整。

核心交付应让学生解释清楚：目标如何产生、每个关节如何求得、骨长如何保持、位置解如何恢复旋转、FK 如何验证、不可达与退化为何发生，以及扩展方法相比基线是否有价值。

## 2. 方案比较与已选路线

| 方案 | 方法与代价 | 结论 |
| --- | --- | --- |
| A：分层求解 | 胶囊几何产生掌部目标；手臂求腕部位置；固定腕部后求各指。各层可单独验证，能清楚解释失败来源。固定掌部可能使部分手指无解，需要在同一掌部下搜索接触区域或报告失败。 | 用户已选择。 |
| B：联合求解 | 同时调整手掌、手臂、五指，使接触与姿态共同优化。可行域更大，但变量、耦合、初始化及失败解释更复杂。 | 本次不采用。 |

这是一个完整课程项目规模的工作。先建立 FK、基线、形状求解、手指与场景闭环，再加入研究扩展；不把浏览器参考点动画直接搬进 Unity 当作 IK 结果。

## 3. 边界与实现者可自行决定的事项

### 3.1 必须满足

- 自写任意串联骨链 FK、自写 Two-Bone、FABRIK 与形状求解流程；不依赖现成 IK 求解节点。
- 所有最终显示姿态由局部关节旋转经自写 FK 得到，Unity Transform 只接收结果。
- 固定每段骨长；不通过改缩放、改骨长或直接搬动指节来迎合目标。
- 区分目标参考曲线、求解点、FK 重建点以及 Unity 显示骨架。
- 清楚报告成功、不可达、退化回退、形状拟合失败、未收敛、接触失败。
- 成功抓取需要独立的手指检查；掌心接触只触发游戏锁定。
- 保留现有玩家移动、角色动画、水体和池厅展示，并把新控制接到同一场景。

### 3.2 本次不包含

- 力闭合、摩擦、真实压力、软组织变形、布娃娃、抬起或搬运人物。
- 手臂与建筑、水体的完整碰撞规划，手指之间的完整自碰撞求解。
- 手掌与五指联合改变目标的全局优化。
- 声音制作、新美术资产采购、WebGPU 部署或正式游戏菜单系统。

包覆检查针对人物胶囊和手指骨段代理。正式展示使用关节点与 LineRenderer 连线，不要求实体手部模型；碰撞计算中的骨段半径是可调代理尺寸，不是 LineRenderer 已经自带了物理碰撞。掌部接触面需要标定；建筑碰撞和可能存在的辅助可视物体不在此数学保证范围内。

- 主手臂 8 段是展示候选，算法接口支持任意段数和非等长骨长，不把 8 写死。两段解析链继续作为独立实验预设；可先用两段和四段测试，再运行八段。

- 正式大厅预设先以新增六段各 8 单位、数组 `[8,8,8,8,8,8,8,7]`、总长 63 作为待验证起点，为约 55 单位的目标距离留出一定弯曲余量。具体长度需采样大厅可站立区域、反算对应腕目标后确定；63 不是已经通过验证或由用户指定的最终值。

- 首轮成功标准为五指全部达到所选接触区域并通过检查；部分成功单独显示，随后释放。
- 接近方位、滚转、采样周期、包覆时间、形状参数、误差阈值和迭代上限均可在运行面板调整。

除明确标为作者提案的尺寸、接近动画时间等项目外，上述静止优先、时序、采样、成功标准和参数可调均已由用户确认。实现者可自行选择 UI 布局、类型与文件拆分、缓冲区复用、线性方程求解方式和测试工具。调整数值默认值时保留用户面板设置，不静默覆盖用户已确认的时序。

### 3.4 分阶段目标

1. **当前首轮：静止人物抓取。** 使用固定的真实竖直胶囊，不处理目标逃跑或空中运动。每轮开始取得快照并固定，先完成手臂 FK/IK、腕掌变换、手指包覆与释放。人物可在两轮之间手动换测试位置；运行面板也可选择多个静止测试点，不能在正在包覆时拖动胶囊。
2. **后续：移动人物与周期取样。** 恢复玩家自由移动，默认仍以 3 秒为取样周期；每轮根据一次快照接近，通过当前实际胶囊判定命中或落空。移动时的帧内接触、异常锁定恢复属于该阶段验收。
3. **课程完整交付：动态轨迹、三类求解器、研究对照。** 保留课程要求的至少 10 秒动态目标动画与系统实验。它们不作为当前静止抓取第一轮的前置条件。

第一阶段固定人物的实验控制与“掌心接触后抓取锁定”分别记录。若使用 PlayerMovement 的测试锁定，应由单独的实验拥有者持有，结束测试时释放；不能借静态模式掩盖抓取状态机是否正确获得/释放自身锁。

## 5. 分层数据流与公共结果

```text
实际 CharacterController → CapsuleSnapshot
     ↓ 每轮开始时的 3 秒周期快照 + 几何策略
PalmPoseTarget → WristPoseTarget
     ↓ 选定的手臂位置求解器
关节点 → 局部旋转 → 自写 FK → 已验证的腕/掌姿态
     ↓ 固定实际腕部 + 实际胶囊
五组接触候选 → 各指 IK → 自写 FK → 接触/穿入/限位检查
     ↓
通过的局部旋转 → Unity 显示；统计和失败原因 → 调试面板
```

统一手臂接口的概念为：

```text
Solve(chain, rootPose, wristTarget, pole, settings, previousPose) -> SolveResult
```

`SolveResult` 至少携带局部旋转、求解点、FK 重建点、末端误差、最大骨长误差、迭代与 FK 调用次数、耗时、主状态、原因、实际使用的回退方法及形状拟合误差。

主状态至少包括 `Success`、`Unreachable`、`InvalidInput`、`DegenerateFallback`、`NotConverged`、`ShapeFitNotFound`、`ContactFailed`。回退后的结果可以满足位置误差，但面板仍显示其原始失败与回退身份。没有全局不可行性证明时，数值拟合失败不能被描述为已经证明无解。

手臂位置成功、腕部朝向成功、掌心触发和五指包覆结果分别记录，避免把它们压成一个模糊的布尔值。

## 6. 坐标、骨链与自写 FK

### 6.1 坐标与表示

世界坐标与 Unity 一致：Y 向上，X 向右，Z 向前；角度存储明确标注 radians 或 degrees。采用列向量与父世界变换乘子局部变换的约定。

每个串联关节记录父索引、静止局部位移 `d_i`、静止局部旋转 `Qrest_i`、可变旋转 `Qdelta_i`、骨骼主轴与辅助轴。每段骨长从静止父子关节间距确定；渲染器子物体可以有非单位缩放，但不能成为求解骨架的祖先。

“骨架及其父层级缩放为 1”具体指这些 Transform 的 Inspector 中 `Scale X=1、Y=1、Z=1`。例如子关节局部间距为 2，而父物体整体 Scale 为 2，实际世界间距会变成 4；非均匀缩放还会使长度随方向变化。首轮直接用关节间距定义骨长，因此保持求解层级不缩放。需要更长的手臂时，显式改骨长和关节间距；仅装饰用的子物体可以单独缩放。此约定与人物胶囊保持竖直是两件不同的事。

本文的变换约定为：

\[
T_i^{local}=\operatorname{Translate}(d_i)
\operatorname{Rotate}(Qrest_i Qdelta_i),\qquad
T_i^{world}=T_{parent(i)}^{world}T_i^{local}.
\]

根关节由给定根坐标框架与根局部关节旋转组合。位置由矩阵作用于原点获得。一个 N 段位置链有 N+1 个关节点；腕部是末端独立朝向关节，其朝向自由度不增加位置链段数。

自写 FK 操作纯数据，不能以 `Transform.position` / `Transform.rotation` 作为计算过程的替代。Unity 只用于读取初始标定数据以及验证引擎显示结果是否匹配。

核心职责明确为：本项目 C# 算法产生目标、关节点位置或关节角度，恢复局部旋转并运行独立 FK；Unity 提供 Vector3、Quaternion、矩阵等基础运算、脚本运行和 LineRenderer 显示。Unity 的父子 Transform 会在应用局部旋转后自动传播世界变换，这可以用于显示及交叉核对，但不能代替课程要求的自写 FK，也不会仅凭放置一个腕目标就替本项目运行 IK。被考核的核心不调用完整 IK 库或引擎现成求解节点。

### 6.2 位置解恢复旋转

对每段，使用求解方向 `normalize(p[i+1]-p[i])` 对齐静止骨轴。第二个方向通过上一帧骨架的辅助轴以最小旋转运输到新方向，再正交化，构造确定的空间坐标框架。

若 `Brest_i` 是该关节本地静止骨轴框架，`Bdesired_i` 是世界目标框架，则：

\[
R_i^{world}=Bdesired_i Brest_i^{-1},\quad
R_i^{local}=(R_{parent(i)}^{world})^{-1}R_i^{world},\quad
Qdelta_i=Qrest_i^{-1}Q_i^{local}.
\]

其中静止骨轴是由静止子位移定义的本地方向，不假设所有素材都沿同一全局轴。首次解使用 pole 产生辅助轴；辅助轴接近平行或方向反转时，使用上一有效法线，再使用与目标方向最不平行的坐标轴。四元数与前帧取同一半球，避免符号跳变。

位置不能唯一确定 twist；上述运输规则就是本项目对 twist 的明确选择。腕部世界旋转最后由掌部目标指定，再转换成本地旋转。所有段重新运行 FK，验证恢复后端点、每段长度与位置解一致。

不能在验证之后再逐关节随意 Slerp 旋转并仍显示旧的“成功”指标。平滑目标输入或在求解目标中使用前帧偏好；如对最终旋转插值，必须重跑 FK 和约束检查。

## 7. 掌心接触、手掌方向与腕部目标

### 7.1 接触几何

胶囊数据为中心 `c`、单位轴 `a`、半径 `r`、总高 `h`，半轴线长度 `s=max(0,h/2-r)`。轴线端点为 `A=c-sa`、`B=c+sa`。

给定点 `x`，到轴线最近点：

\[
q=c+a\,\operatorname{clamp}((x-c)\cdot a,-s,s),\qquad
\phi(x)=\|x-q\|-r.
\]

`phi=0` 是表面，正值在外部，负值在内部。接近方向 `n` 是从胶囊指向手臂根部、投影到垂直于 `a` 的平面后归一化的方向；可绕 `a` 施加可调方位角。退化时复用上一方向，再使用配置的首选侧向。

首轮掌心目标在躯干中心截面：`P*=c+r*n`。标记点 P 放在实际掌部接触面上，不能把掌部几何中心与接触标记混用。现有 PalmFrame 若不在接触面，则另设标定的 `PalmContactFrame`，其与 Wrist 的刚性偏移固定。

### 7.2 朝向的确定

掌部接触框架定义：局部 +Z 为掌心朝向人物的方向，局部 +Y 为沿人物轴向的参考方向，+X 由这两者构造为正交坐标框架。

默认朝向 `forward=-n`，参考 `up=a`。滚转是在 `forward` 轴上的可调旋转，默认零。由两个不平行向量构造旋转；不直接独立插值三个 Euler 角。

“滚转默认 0°”表示掌心已经朝向人物后，不再额外绕掌心法线拧转。例如掌心朝一面墙时，仍能保持掌心朝墙而把整只手顺时针转 30°，这 30° 就是额外滚转。零值是所选抓取参考朝向的零扭转，不要求 Wrist 的世界 Rotation/Euler 全为零，也不禁止手掌为了朝向人物而旋转。

四指与拇指的包覆方向用胶囊切向 `t=a×n` 定义，四指正向绕行、拇指反向绕行。素材中骨轴与这些方向之间的关系由标定得到，不能把接触框架的轴直接当作所有指节的铰链轴。

### 7.3 腕部反算与层间契约

标定的腕到接触框架变换记为 `T_WP`。要求的接触框架世界变换为 `T_P*`，则腕部目标为：

\[
T_W^*=T_P^*(T_{WP})^{-1}.
\]

手臂求腕的位置，末端独立腕关节匹配腕的方向。手指阶段使用 FK 实际重建的腕部，不使用尚未到达的理想腕部。

固定掌部后，只允许在同一掌部下调整各指的接触候选。若整体失败，释放并在下一轮重新生成目标；不在手指求解内部暗中移动手掌。未来若要改变此契约，应作为联合求解的新范围讨论。

## 8. 手臂三类求解器

### 8.1 Two-Bone 解析基线

限定两段位置链。令目标距离为 `d`，两段长为 `l0,l1`，目标方向为 `e`，pole 在垂直于 `e` 的平面中给弯曲单位向量 `b`：

\[
x=\frac{l_0^2+d^2-l_1^2}{2d},\quad
y=\sqrt{\max(0,l_0^2-x^2)},\quad
p_1=R+xe+yb.
\]

正常区域使用现有公式；不可达时报告并显示保持骨长的最近距离边界姿态。近根、近伸直、pole 共线时根据缓存弯曲平面作显式退化处理。两段解析预设与迭代/形状方法可在同一实验界面切换；不把 Two-Bone 伪装成可直接求任意多段链的方法。

### 8.2 FABRIK 迭代基线与八段计算量

自写前后向重定位，使用原始骨长。给定相邻点后，另一点按单位方向乘对应骨长更新；一遍从目标向根回推，另一遍固定根向末端推进。设置误差终止、迭代上限与零方向回退。方法来源为 Aristidou 与 Lasenby 的 FABRIK [R1]。

八段对应九个关节点。一次完整前后向遍历约有 `2N=16` 次骨段重定位；若示例上限为 32 轮，则约 512 次骨段重定位，外加误差与旋转恢复/FK。这里是操作数量估算，不是当前程序已经测得的耗时或收敛保证。普通 FK 和每轮 FABRIK 的工作量随段数线性增加；数值 Shape IK、碰撞与多候选搜索另计成本。真正需要验证的是不同骨长、目标和形状限制下是否收敛，不是八段必须有专用八段解析公式。

自由串联链距离可行域：

\[
L=\sum_i l_i,\quad r_{min}=\max(0,2l_{max}-L),\quad r_{max}=L.
\]

超过边界属于可证明的位置不可达；位于边界内仍可能遇到本次数值迭代未收敛，不能把这两种情况混为一谈。无关节限位的手臂作为课程基线；本次硬限位集中于手指。

### 8.3 三种形状作为同一类求解器的形状族

圆弧、波形、螺旋全部属于形状型。解析、迭代、形状三类由 Two-Bone、FABRIK、Shape IK 覆盖。

给定根 R、腕 W，`d=|W-R|`、`e=(W-R)/d`。pole 与前帧生成垂直于 e 的基向量 b，`c=e×b`；三者构成曲线参考框架。接近零距离时不构造非法曲线，进入明确回退。

设 `u∈[0,1]`，待求振幅/弓高为 H：

- **圆弧**：`rho=d²/(8H)+H/2`，`beta=2 atan(2H/d)`，`v=(2u-1)beta`；`C=R+(d/2+rho*sin(v))*e+(H-rho+rho*cos(v))*b`。H 趋零时使用直线极限。首轮仅取小弧范围 `0≤H≤d/2`，不声称覆盖所有目标和总骨长组合。
- **波形**：`C=R+u(W-R)+H*sin(2*pi*k*u)*b`，k 是配置的正整数，默认 1。
- **收口螺旋**：`C=R+u(W-R)+H*sin(pi*u)*(cos(2*pi*k*u)*b+sin(2*pi*k*u)*c)`，默认 k=2。它明确是两端收口的空间形状，不称为严格等半径圆柱螺旋。

三种曲线都固定两端。用户的形状强度是振幅偏好/允许范围，振幅的实际数值由端点和离散骨长共同求出，并在面板显示“偏好值 / 实际值”。改变形状参数并不改变目标运动轨迹；参考曲线描述一帧内整条手臂的姿态。

### 8.4 形状参数与离散骨长的联合拟合

未知量为 H 与有序内部采样位置 `u1...u[N-1]`，端点 `u0=0,uN=1`。约束是每条弦的长度，而不是曲线弧长：

\[
f_i(H,u)=\frac{\|C(u_{i+1};H)-C(u_i;H)\|-l_i}{L}=0.
\]

使用正的采样间隔参数化，归一化后累计得到 u，防止参数次序颠倒；固定一个 logits 作为规范以消除共同平移冗余。振幅使用有界参数或带边界的线搜索。以按累计骨长分配的 u 和若干确定的振幅种子初始化，优先使用上一帧可行参数。

用阻尼最小二乘求解 `min sum(f_i²)`：有限差分构造 Jacobian，解 `(JᵀJ+lambda I)delta=-Jᵀf`，步长回溯，只接受残差下降的有限值步骤。拟合首轮每种子最多 40 步、最多 6 个种子；总评估次数计入耗时。

每段弦长误差小于 `1e-6*L` 后，恢复局部旋转并运行 FK。FK 的段长由原始静止位移决定，不能为了精确复制未收敛曲线点而改长度。只有最终 FK 端点与骨长也通过阈值，才报告形状成功。

若指定形状范围拟合不到：

1. 保留原始目标、残差和失败原因，报告 `ShapeFitNotFound`。
2. 普通手臂本身可达时，允许 FABRIK 产生保持骨长的回退姿态，明显标记 `fallback=FABRIK`，不把它计为形状求解成功。
3. 原始目标超出普通链距离可行域时报告 `Unreachable`，不靠放大振幅或伸长骨头掩盖。

等弧长采样可用作初始化，不能被用作骨长正确性的证明。曲线参数数值失败也不能被宣称为形状全局不可行性证明。

## 9. 手指基线：固定掌部下的接触候选与限位 CCD

### 9.1 指链、轴与标定

每指默认 3 段实体骨。根部包含一个外展自由度与一个屈曲自由度，后两关节各一个屈曲自由度，共 4 个标量；可以用同位的虚拟旋转节点表达，虚拟节点不算实体骨长。

各指的根相对 Wrist 固定。保存原始静止旋转，用自写 FK 合成外展、屈曲和静止姿态。标定明确每个轴和正向，验证正屈曲是否朝人物包覆。拇指通过不同的静止根框架体现对向关系，不把它复制成第五根同向手指。

限位是风格化模型的可调设置，不声称是真实人体解剖数据。初始作者建议：四指屈曲依次 `[0,90]、[0,105]、[0,80]` 度，根外展 `[-20,20]` 度；拇指在其对向静止框架下使用 `[0,65]、[0,90]、[0,80]` 度，外展 `[-40,40]` 度。若素材轴相反，转换轴符号，不破坏限位意义。

### 9.2 接触点随人物尺寸和当前手掌产生

每根指的高度来自实际指根在胶囊轴上的投影，再约束在配置的躯干接触带内。截面处用胶囊的真实截面半径与法线计算，不把半球顶部当成同半径圆柱。

首选角度可复用当前模板：四指 `115、125、135、145` 度，拇指 `-65` 度，正负由切向 t 约定。模板是候选区域，不是保证可达的最终答案。每指按照固定次序尝试角度偏移 `0、-10、+10、-20、+20` 度及接触带内的小幅高度调整；候选数设上限并计入总耗时。

若表面点为 S、外法线为 nS、指尖代理半径为 rf，则指尖关节目标为 `g=S+rf*nS`。骨段代理使用独立的半径元数据；不把缩放过的可视网格宽度隐式带入骨架坐标。

### 9.3 CCD 更新及接触路径

对每个允许转轴，从末端向根更新。轴方向为 a、轴原点 o，当前指尖向量与目标向量投影到轴的垂直平面，使用：

\[
\Delta\theta=\operatorname{atan2}(a\cdot(v\times w),v\cdot w).
\]

把修正角限制在关节限位内，重新运行该指 FK；每轮检查误差，最多 32 轮。轴、向量投影近零时跳过该更新并记录原因。CCD 的逐轴逼近属于已有方法，参考 Kenwright [R2]。

指尖不会从张开位置直接沿穿过胶囊的弦线插到背面。接触规划先到胶囊外侧预接触点，再沿目标截面的外侧弧线逐步转向最终角度；收拢进度控制参考点的径向距离和绕行角。参考路径只引导求解，显示的关节仍必须来自固定骨长 FK。

### 9.4 独立检查与失败处理

每段手指视为线段加半径的胶囊代理。求该线段与人物轴线段的最短距离 dseg，清空量 `clearance=dseg-(r+rf_segment)`。检查整个骨段，不能只检查指尖或关节点。

在人物锁定后的包覆、停留与张手阶段，显示姿态必须满足关节限位、有限值和所有骨段的清空量容差。CCD 的旋转增量做步长回退；无法产生通过检查的候选时，保留在同一冻结胶囊和固定腕部下的上一安全姿态。检查针对实际提交的每帧姿态，不声称实现了连续时间扫掠碰撞。

**作者选择：自由移动阶段不扩展为完整人物—手指碰撞系统。** 等待、接近和手臂复位时，玩家可以走入张开的手指代理；此时显示碰撞诊断，但不宣称硬性非穿入，也不以“上一帧安全”推断本帧安全。掌心接触候选成立后，先验证当前张开指姿态与帧末胶囊；若已经穿入，则报告 `CaptureRejected / InitialOverlap` 并复位，不进入包覆硬约束阶段。人物不会因为这种无效接触而持续被锁住。任何外部系统在锁定中改变胶囊尺寸或人物位置，也应中止本轮并释放，不能继续复用旧的安全姿态。

包覆成功要求：五指末端都进入选定表面接触区域的容差、所有指段未超出允许穿入容差、限位及 FK 误差通过。每指保存成功/无可用候选/限位阻挡/穿入阻挡/未收敛状态。有限候选搜索失败不等于已经证明固定掌部下所有接触均无解。

失败时不拉长手指、不锁住人物无限等待；显示部分包覆与原因，短暂展示后松手，下一轮重新采样目标。五指成功是首轮默认阈值，可在设计审阅时调整，但结果必须始终报告每指真实状态。

## 10. 游戏状态机与抓取判定

| 状态 | 采样、控制及退出 |
| --- | --- |
| 等待 / 配置 | 首轮人物固定站立，选择算法和形状；记录合法张开姿态与复位目标。等待状态遇到 3 秒采样时刻，采样胶囊并启动一轮。后续移动阶段在此允许人物自由移动。 |
| 固定快照接近 | 本轮固定胶囊样本与掌部目标，IK 每帧运行，目标路径平滑。接近动画暂提议 2 秒，可在面板调整；采样时钟到点不改变本轮目标。 |
| 到达检查 | 通过实际 FK 掌心 P 与当前真实胶囊检查触发，不以动画百分比代替接触。到达时间用尽且未触发则显示 Miss 并复位；不继续无限迭代等待。 |
| 掌心接触 / 锁定 | 接触候选经帧末姿态重建及初始清空检查通过后，保存人物当前帧位置和已验证的实际腕部姿态，锁定玩家移动；冻结实际腕部，按真实胶囊重新生成各指目标。标记 CapturedPendingWrap。 |
| 手指包覆 | 固定掌部，沿外侧路径逐指求解并验证。结束后五指检查全通过则 GraspConfirmed，否则 PartialContact / ContactFailed。 |
| 停留 | 1 秒，完整显示成功或部分包覆与原因。腕部保持。无合法姿态等异常允许提前中止并释放。 |
| 张手释放 | 0.5 秒，保持抓取锁，反向使用本轮已验证的指姿态序列张开，每次提交仍运行 FK 与清空检查；到达本轮起点的安全张开姿态后解除抓取锁。异常路径无条件释放自身抓取锁。 |
| 手臂复位 | 1 秒回到初始目标，手臂继续由求解器或明确回退驱动；之后至少等待 0.75 秒，再在下一个允许的采样时刻开始下一轮。静态实验的人物仍保持站立。 |

周期计时由独立状态控制器管理，不能让几何目标生成器、手臂求解器、手指驱动各自控制整轮动作。3 秒是允许读取并发起抓取的周期，动作时序合计已超过 3 秒，因此忙碌期间的采样机会跳过，不排队累积旧快照；复位且满足 0.75 秒等待后，使用下一次新样本。

### 10.1 掌心实际接触

第一阶段使用静止胶囊与实际 FK 掌心标记的 `phi(P)`，并检查本帧掌心移动线段，避免手掌跨过表面仍未触发。只在接近阶段、上一帧在外侧且本帧到达表面容差或路径经过表面时产生候选；触发不依赖理论目标或动作百分比。

以下移动胶囊与相对运动处理留作第二阶段：标记路径检测使用相对本帧前后胶囊平移的线段到轴线段距离，前提是人物轴向和尺寸在一帧内不变；取首次命中的时刻与表面法线。

阈值首轮为 `epsilonContact=max(1e-4 m,0.01*r)`，允许 skin 级的小容差，并在面板显示。**作者选择：人物冻结在本帧 PlayerMovement 已经到达的位置，不回退人物位移。** 帧内命中给出相对于胶囊的局部表面点和法线；把该局部表面点随胶囊平移到帧末，重建掌部位置与方向，再反算腕部并重新求手臂。采用重建后的 FK 实际掌心与帧末胶囊重新检查接触及初始指段清空。

只有重建结果通过，才一起提交手部姿态并锁定玩家；手臂不可达、未收敛或初始手指穿入时报告 `Miss / CaptureRejected`，本轮不锁定。这样帧内检测用于发现接触候选，最终锁定依据始终是帧末可验证的骨架姿态；不把曾经穿过人物但末帧已经分离的轨迹直接计为成功。

执行顺序固定为：`PlayerMovement.Update` 完成本帧移动 → 抓取协调器在 `LateUpdate` 采样实际胶囊、运行手臂与接触检测/必要的接触重建 → 验证 → 获取移动锁并提交姿态。手指在后续锁定阶段由同一协调器求解。旧旋转驱动在新模式下停写；玩家动画依赖的速度在获取锁时清零，最迟下一次动画更新反映静止。

### 10.2 人物锁定与恢复

抓取锁定接口由 PlayerMovement 显式支持，清零请求速度和实际速度，屏蔽移动及跳跃，冻结抓取时位置与竖直速度；不把人物临时挂到手掌下，也不靠反复禁用 CharacterController 来锁定。角色 Animator 收到静止速度，避免位置锁定后还播放奔跑。

释放、求解异常、引用丢失、组件禁用、离开 Play Mode 都必须释放自己持有的锁。使用拥有者/令牌区分其他移动锁定来源。解除后重新采集接地状态，若在空中则从清零的竖直速度恢复重力，不能保留抓取前的跳跃冲量。

首轮人物静止站在地面；空中接触属于后续移动阶段的鲁棒性用例。人物竖直胶囊和当前位置在抓取锁定期间保持。水体、角色外观不参与 IK 计算。

## 11. 研究扩展：固定掌部下的多点包覆引导 IK

这是进阶系统之后的一项明确扩展候选，仍遵守分层 A。它不能仅以“多加一种曲线”交差，也不宣称学术新颖性或未经实验的优势。

### 11.1 问题与对照

手指末端 CCD 只直接追踪指尖，关节可能挤在一侧，且在胶囊非穿入检查下容易停滞。扩展在固定掌部下，同时引导中间指节沿胶囊外侧包覆，并偏好时间连续的角度。研究问题是：在相同末端、限位、骨长、非穿入要求和预算下，是否能增加包覆成功率或减少帧间姿态变化，代价是多少。

### 11.2 未知量、目标和约束

每根指独立求 4 个关节角 theta。FK 给出关节/指尖 `p_i(theta)`。外侧参考点 `G_i` 按当前接触截面、绕行方向、闭合进度和各段累计长度产生；它们只是中间形状偏好，不要求离散骨点恰好落在圆弧上。

\[
E(\theta)=w_g\|p_{tip}(\theta)-g\|^2
+w_s\sum_{i\in internal}\|p_i(\theta)-G_i\|^2
+w_t\|\theta-\theta_{previous}\|^2.
\]

硬约束：固定掌部、关节角盒限位、每段原始骨长、骨段清空量不低于容差、全部有限值。指尖接触是最终成功判定，不能因加权目标下降就视为成功。FK 参数化自动保持骨长。

### 11.3 求解更新与伪代码

对旋转轴 a_k、轴原点 o_k，受该关节影响的点有导数：

\[
\frac{\partial p_i}{\partial\theta_k}=a_k\times(p_i-o_k).
\]

由链式法则计算 E 对每个角的梯度。按固定关节次序做投影坐标下降：尝试 `theta_k=clamp(theta_k-eta*dE/dtheta_k,lower,upper)`，运行 FK，只有能量下降且骨段清空检查通过才接受，否则减半步长，达到最小步长后跳过该轴。通过与中心差分的对照验证梯度实现。

```text
for each finger:
    seeds = previousSafePose, currentSafeCCDProposal, calibratedOpenPose
    discard invalid or colliding seeds
    for each remaining seed within the same evaluation budget:
        repeat bounded sweeps:
            build current FK and wrap guide points
            for each allowed joint coordinate:
                derive point Jacobians and scalar energy gradient
                backtrack a limit-clamped step
                accept only lower energy and valid segment clearances
            stop on contact success or stalled improvement
    select feasible candidate with the best contact result, then energy
    otherwise return explicit ContactFailed / NotConverged and last safe pose
```

参考点在一个内层优化期间固定；下一帧/闭合阶段更新后重新建立目标，避免在回溯过程中偷偷改变能量函数。对照方法使用相同的参考指尖轨迹、候选接触集、限位和碰撞检查；新增部分只包含中间包覆偏好、时间项与对应更新流程。

这是非凸局部方法，不能保证找到所有可行解。初始姿态、接触模板或关节范围不合适时会失败，必须计入结果；不能过滤掉难例再声称优于基线。

### 11.4 对照与消融

- 基线：带相同限位和非穿入接受条件的末端 CCD。
- 扩展：末端 + 多点包覆 + 时间项。
- 消融：去掉多点项；去掉时间项。
- 在相同人物尺寸、掌部姿态、指链、初值、轨迹、帧率和候选集上比较。
- 分别按相同 FK 评估预算和相同迭代上限报告结果，不能把更大计算量隐去。
- 报告接触成功率、最大穿入、末端误差、每段骨长误差、角速度/角加速度、总耗时和失败类型。

若扩展没有稳定收益，报告负面结果和适用边界，不能仅凭动画更好看判定研究问题成立。

## 12. 误差、测试与课程对应

### 12.1 统一指标

\[
e_{end}=\frac{\|p_N^{FK}-W^*\|}{L},\quad
e_{bone}=\max_i\frac{|\|p_{i+1}^{FK}-p_i^{FK}\|-l_i|}{l_i},\quad
e_{rebuild}=\max_i\frac{\|p_i^{FK}-p_i^{solve}\|}{L}.
\]

`e_bone` 使用逐段相对误差，是本项目明确选择的定义；课程文件提到归一化误差但未给出单独的统一公式，因此报告同时保留米单位绝对误差和此定义。零/近零长度输入单独归类，不能作分母。

运行成功门槛首轮为 `e_end≤1e-4`、`e_bone≤1e-5`、`e_rebuild≤1e-4`，比课程验收 `1e-3` 留余量。腕部姿态误差另报角度；手指接触容差 `max(1e-4 m,0.01*r)`，穿入容差同量级并明确记录，不能把显示四舍五入当作通过。

### 12.2 基础验收

- 固定随机种子，通过随机合法关节姿态的自写 FK 产生至少 1000 个可达位置目标；保证数据可重复。
- Two-Bone 和 FABRIK 在各自支持的链结构上验证：可达样本平均归一化末端误差 `<1e-3`，每例骨长误差 `<1e-3`。
- 原样报告全部样本、未收敛与回退率；不能只统计成功样本平均值。
- 独立记录根部附近、最小可达半径、完全伸直附近、外侧/内侧不可达、pole 共线/近零、零长度、不合法数字、非等长骨。
- 旋转恢复额外测试非标准骨轴、非零静止旋转、根部平移旋转、方向 180° 翻转与多帧 twist 连续性。

### 12.3 形状验收

- 已知可行的曲线参数和采样先构造点，再提取骨长与端点，回交求解器；这组测试明确标注为形状闭环测试，不冒充固定骨架下任意目标都可行。
- 另用固定骨架连续移动腕部，覆盖形状可拟合、达到参数边界、拟合失败和普通骨链不可达；报告原始形状成功率与 FABRIK 回退率。
- 两段共同问题上比较 Two-Bone、FABRIK 和适用的形状方法；8 段共同问题上比较 FABRIK 与形状方法。不同段数的用时不能作为同问题的直接优劣结论。
- 展示实际 H、u 分布、形状曲线、固定骨长离散点及 FK 误差。

### 12.4 游戏与研究验收

- **首轮静态验收**：人物固定在一个位置，手臂正确求解到掌部目标，完成五指包覆、停留、张手和复位；至少一组完整成功配置及手指够不到/穿入阻挡的失败配置。
- 首轮另选若干固定目标位置分轮测试；3 秒采样不打断正在执行的动作，确认时序为 1 / 1 / 0.5 / 1 / 0.75 秒。
- 抓取控制器的锁定/释放、异常与停止运行后的恢复需要独立验证，不能因为静态实验本来已固定人物而跳过。
- **后续完整课程验收**：至少 10 秒连续的“动态目标 → IK → 局部旋转 → FK → 角色显示”动画，覆盖多轮成功抓取和明确失败用例。
- 移动阶段验证玩家接触前能走、跑、跳；接触后无位移，动画速度归零；释放、异常和停止运行后恢复。增加快照过时导致人物逃开、低帧率掠过、空中锁定等用例。
- 运行时切换算法只在等待/复位完成时生效，忙碌时排队并显示下一轮配置，避免同一帧换骨架。
- 研究扩展按第 11 节的同问题比较与消融输出表格，报告成本、失败及适用边界。

不为纯 UI 布局写镜像实现的测试。测试重点放在数学不变量、退化行为和移动锁定恢复，这些会直接影响课程结论或玩家控制。
